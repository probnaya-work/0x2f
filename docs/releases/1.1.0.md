# 0x2F 1.1.0

Review the context before continuing a task through the same or another agent.
[Preview guide](../continuation-preview.md) ·
[Exact release qualification](1.1.0-qualification.md).

## Changes since 1.0.0

- Local Web and TUI show the next fresh session's task prompt before retry,
  reopen, correction or answer-and-continue. Select the next harness, review
  instructions and prior-result delivery, then explicitly start.
- Draft corrections and answers remain editable on cancellation and are saved
  on the confirmed start attempt. A changed task, target or context refuses
  the reviewed start before creating another run.
- CLI adds `2f preview <id> [--provider <id>]` and guarded
  `2f rerun <id> --preview <preview-id>`. Existing direct CLI reruns remain.
- Previous results show full, excerpt or reference-only delivery under the
  existing context budget; binding user instructions are not shortened.
- Lost or failed responses do not automatically retry execution. Local Web
  reconciles consumed drafts against authoritative task state and preserves
  newer edits. An open review cannot silently advance to another run.
- CI verifies the installed package through CLI, real TUI and detached worker.
  Test fixtures wait for complete frames and stop writers before cleanup.

The preview describes the task prompt, not every hidden harness instruction
or file an agent may read. It does not freeze the checkout or guarantee the
agent follows instructions. Existing context compilation and task storage
formats are preserved. The phone/relay protocol does not gain full prompts.

## Install, upgrade and rollback

```sh
npm install -g --prefix "$HOME/.local/0x2f-1.1" 0x2f@1.1.0
export PATH="$HOME/.local/0x2f-1.1/bin:$PATH"
2f version  # 1.1.0
```

Quiesce workers and external writers before changing executables. Retain the
previous prefix and a consistent private backup. This release introduces no
task-data migration. Existing saved results and run history remain readable.
Keep replay and uncertainty receipts intact. The
[1.0.0 operations and rollback rules](1.0.0.md#install-upgrade-and-rollback)
continue to apply, including active-pairing authority.

## Supported scope and evidence

The supported core remains local CLI, TUI and desktop Web on macOS arm64 and
Linux x86_64 with Node.js ≥20 and a supported authenticated harness. Phone
companion and operator self-hosting remain experimental; physical phone and
public hosted-service support are not established by this feature.

The [development feature qualification](continuation-preview-qualification-2026-11-15.md)
records six platform/Node suites, installed-package checks, both terminal
palettes, local-browser flows and a small live Codex → OpenCode inspection.
Its artifact is distinct from the final versioned release. The
[release record](1.1.0-qualification.md) attributes final package bytes, CI and
public registry checks separately.

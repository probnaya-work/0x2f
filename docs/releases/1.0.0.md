The first stable release of the local CLI, TUI and desktop Web.

## Release scope

The release core is local CLI, TUI and desktop Web on macOS arm64 and Linux
x86_64, with Node.js ≥20 and an installed, authenticated supported coding
harness. Tasks, their original requests, notes, decisions, saved run input
and results persist across sequential runs and provider handoff.

READY means a provider result is available for review. Independent checks
and human acceptance are separate facts. Harness permission, resume and
cancellation behavior follows the [observed compatibility table](../harness-compatibility.md).
Historical live harness receipts retain their tested versions and artifact
attribution; a version bump does not create new live model evidence.

The phone is an experimental companion browser surface; execution stays on
the host. iPhone observations cover reading, creation, acceptance and the
owner-confirmed design/scroll fixes on earlier named candidates. Exact-final
physical qualification remains required for a supported phone claim.
Android is unqualified. Self-hosted remote access is experimental and
requires operator-owned client and relay origins; no operated service is
supplied. Windows execution, native mobile apps and closed-browser push
are outside this release scope.

## Changes since public 0.3.0

- Remote commands recheck authorization within their execution queue and
  persist replay admission before applying an effect. Uncertain/corrupt
  receipts refuse mutations while reads remain available.
- Phone command bodies retain submitted fields. Offline controls stay
  disabled until authoritative state is refreshed; offline mutations are
  not queued.
- Workspace runtimes have separate browser authentication across ports.
  CLI/TUI neutralize untrusted terminal control sequences in display.
- Linux recovery excludes zombie-only groups while retaining conservative
  behavior for live members and unreadable observations.
- Unknown CLI options fail before effects. Help does not start work, and
  `--` permits literal task text beginning with an option marker.
- Hosted pairing validates separate client/relay origins and HTTPS before
  credential changes or network calls. Deployment templates serve pairing,
  modules and protocol routes consistently. Crypto parameters and authority
  are unchanged; pairing derivation moves off the main thread when possible.
- Desktop and phone results use compact prose, distinct headings and green
  command formatting. Technical receipts follow the outcome. Drafts and
  focus survive updates; async reads have loading, failure and retry states.
  The phone identity strip no longer changes scroll geometry.
- Both TUI themes give results and questions more width, put bookkeeping
  below current content, distinguish the primary action, and use a padded
  editor. Terminal widths respect graphemes and cell geometry, code keeps
  indentation, and long reports retain all saved evidence. Up/Down follows displayed soft
  wraps, exact-width newlines do not add blank rows, and edits retain grapheme boundaries.

[qualification history](public-release-qualification-2026-11-14.md), and
[approved screenshots in both themes](1.0.0-screenshots.md).

## Install, upgrade and rollback

Install the versioned package into a separate prefix:

```sh
npm install -g --prefix "$HOME/.local/0x2f-1.0-review" 0x2f@1.0.0
export PATH="$HOME/.local/0x2f-1.0-review/bin:$PATH"
2f version
cd /path/to/your/repository
2f init
2f providers
2f new "Inspect retry handling; preserve the public API" --provider codex
2f open 1  # use the actual ID returned above
2f tui
2f ui
```

Choose a provider actually installed and authenticated on this host. Codex
is an example. Follow the [quickstart](../quickstart.md) and
[commands](../usage.md) for results, notes and handoff.

Before upgrading an existing workspace, quiesce workers and external writers,
retain the old executable prefix, and create a consistent private backup.
The `.work/tasks/<slug>/task.json` / `events.jsonl` interface and atomic task
writes are unchanged; this release introduces no task-data migration.
Use the new prefix to reopen existing tasks and inspect saved results.

New replay/uncertainty receipts are a safety boundary. For active pairings,
retain the new runtime, or revoke pairing before reverting to a runtime
without replay admission. Do not delete receipts to force a retry.
Rollback requires quiescence and the matching previous executable and
consistent state, preserving newer evidence separately. Private restore
disables remote/execution authority. See [operations](0.3.0-operations.md).

## Qualification and publication handoff

The [exact qualification record](1.0.0-qualification.md) contains the
artifact hash, installed-source comparison, six-run platform matrix,
empty-HOME verification, upgrade receipt and remaining gates. No earlier
candidate's checks are relabeled as tests of this package.

Before a supported phone or operated-hosting claim, complete the
[physical checklist](mobile-qualification.md) and qualify valid public HTTPS
client/relay origins from another network. Loopback Caddy tests do not
establish an operated service.

The exact stable archive and current CI receipts are recorded independently
from prior candidates. Phone and operated-service support remains excluded
until its corresponding physical/HTTPS evidence exists.

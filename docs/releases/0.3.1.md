# 0x2F 0.3.1 — candidate changes

Historical candidate notes. Current preparation has moved to
[1.0.0-rc.1](1.0.0.md); the evidence below retains its original attribution.

Unpublished candidate: `0.3.1-rc.8`. No release, tag or registry update has
been made. The public npm version remains `0.3.0`.

## Changes since 0.3.0

- Remote mutations recheck authorization inside the execution queue and persist
  replay admission before applying an effect. Duplicate messages cannot start
  work twice. Uncertain or corrupt receipts refuse mutations and require
  inspection; reads remain available.
- Phone requests decode the JSON bodies used by the production browser. Task
  creation, notes and decision responses preserve their submitted fields.
- Mobile task detail keeps the offline banner visible and mutation controls
  disabled throughout a disconnect. Reconnection refreshes authoritative state;
  offline commands are not queued.
- Separate workspace runtimes retain separate browser cookies on different
  ports. CLI/TUI display neutralizes untrusted terminal controls while saved
  task evidence retains its original bytes.
- Linux recovery excludes zombie-only process groups from liveness checks,
  while live members and unreadable process observations remain conservative.
- Unknown CLI options fail before effects. Command help does not launch work;
  `--` allows literal task text beginning with an option marker.
- The self-hosted Caddy template serves `/pair` correctly. Static Netlify route
  and MIME hints are generated, and the relay installation guide installs
  dependencies at the complete repository root. Legacy environment variables
  are shown through `env`, since shells reject their digit-leading names.
- Hosted pairing requires a separately configured client origin and relay.
  No example service address is substituted. The pairing page must use HTTPS
  (except loopback development) and must have a different origin from the relay.
  Invalid configuration is refused before credential changes or network calls.
  Explicit environment overrides saved hosted origins; flags override both.
- The local TLS verifier normalizes displayed pairing codes and uses synthetic
  execution without inheriting a model account. CI configuration checks macOS
  and Linux on Node 20, 24 and 26 with read-only repository permissions.

The phone UI now separates task text from machine metadata, gives fields a
consistent inset and aligns select indicators. The composer keeps multiline
input on Enter at phone widths; Start task remains an explicit action. Plain
HTTP pairing derives its unchanged 600,000-iteration key in a module worker
when available, with a compatible responsive fallback. No cryptographic
parameters or pairing authority were weakened. The mobile identity strip no
longer changes scroll geometry; live snapshots retain the connected reader and
height-only Safari viewport changes do not rebuild it. Result text uses a compact
14px reading size, explicit heading hierarchy and technical receipts after the
written outcome on both Web surfaces.

Desktop task detail now gives the written result a readable measure and one
scroll surface, with separate typography for prose, metadata and commands.
Loading and read failures have explicit states and retry actions. Live updates
retain the connected composer, draft selection and focus; task rows support
keyboard activation.

The TUI puts the conclusion before changed files and the full result before
request context. Commands use a terminal green; fenced code keeps indentation
and quoted whitespace. Display wrapping and clipping use terminal cell widths
and whole graphemes, including CJK, combining marks and emoji. The final screen
writer also strips untrusted terminal controls. The task rail is narrower and selected titles can use two lines; provider signatures remain visible. Results and current questions precede bookkeeping, completed traces expand on demand, and the primary action has one clear accent. Both themes have distinct reading and editing surfaces, with a padded draft field and fewer competing global shortcuts. See the [TUI follow-up](tui-design-qualification-2026-11-15.md).

The current source also includes the TUI work after the public 0.3.0 checkpoint.
The [earlier audit](prerelease-audit-2026-11-14.md) records that baseline and its
fixes; the [qualification record](public-release-qualification-2026-11-14.md)
records the exact successor artifact and fresh checks.

## Support statement

The qualified core is local CLI, TUI and desktop Web execution on macOS arm64
and Linux x86_64 with Node ≥20 and an installed, authenticated supported
harness. Live candidate work used Codex 0.166.0 and OpenCode 2.2.5; other
harness limits remain in the [version-pinned table](../harness-compatibility.md).
Do not infer identical permission, native resume or cancellation behavior
across harnesses from a common interface.

The phone is a companion browser surface; execution stays on the host.
Responsive desktop captures, encrypted-protocol tests and a Caddy loopback
integration pass do not qualify a physical iPhone/Android or an operated
public service. Those claims remain pending the [physical checklist](mobile-qualification.md).
No hosted service, Windows execution, native mobile app or closed-browser push
is supplied by this release.

## Install, upgrade and rollback

Install the supplied candidate tarball into a separate prefix for review:

```bash
npm install -g --prefix "$HOME/.local/0x2f-candidate" /absolute/path/0x2f-0.3.1-rc.8.tgz
"$HOME/.local/0x2f-candidate/bin/2f" version
```

Use the prefixed command throughout the review so it cannot silently run an
older global installation. Do not publish an `npm install 0x2f@0.3.1` command
until that exact stable version exists in the registry.

Before replacing an existing installation, quiesce workers and external writers,
retain the old executable prefix and make a consistent private backup. Task
layout and atomic task writes are unchanged; task records are not migrated.
New relay uncertainty receipts are a deliberate safety boundary: retain the new
runtime for active pairings, or revoke pairing before reverting to an older
runtime that lacks replay admission. Preserve receipt evidence when inspecting
an uncertain action; deleting the cache is not a safe retry procedure.

For rollback, quiesce the new runtime and restore the matching previous prefix
and consistent old state, keeping newer evidence separately. Private restore
disables remote/execution authority. See the [operations guide](0.3.0-operations.md)
for host supervision, isolation, backup and explicit application of changes.

## Publication handoff

Review the exact artifact hash and qualification receipt, complete the physical
and operated-HTTPS gates for any support claims retained, then run the CI matrix
after an authorized push. A stable version bump changes package bytes and ACP
metadata: pack and install that final stable artifact before publication.
Align the public site, README/install command and release notes to the same
version. Publication, push and tags require a separate user command.

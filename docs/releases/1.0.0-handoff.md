## Before publication

1. Review the final diff and support statement. Local CLI/TUI/desktop Web is
   the qualified core. Phone companion and self-hosted remote access remain
   experimental; do not promote those claims from responsive screenshots
   or loopback integration tests.
2. Complete exact-artifact physical and operated-HTTPS qualification for any
   broader support claim. Record platform/browser versions, interruptions,
   note/decision/permission/cancel/retry, revocation, and another-network
   access. Retain private pairing material outside public evidence.
3. Obtain the separate instruction for commit/push, then run the prepared
   GitHub matrix and inspect its actual result. Local matrix receipts are
   not GitHub CI receipts.

## Authorized publication sequence

After a separate publication instruction and successful stable qualification:

1. Review/publish the exact previously verified archive, with its recorded
   hash. Verify the registry's resulting version, integrity and install path
   from a fresh prefix before advertising it.
2. Create the matching tag/release and attach the reviewed notes and digest.
   Keep repository, npm package and public instructions on the same version.
3. Deploy the prepared website from `release/1.0.0-site` only after verifying
   the npm artifact, matching GitHub release and linked versioned docs. The
   two install snippets, clipboard command and release links are aligned. Its [current public page](https://0x2f.space/) still advertises
   `0x2f@0.3.0` as observed on 2026-11-15. The reviewed replacement is
   `npm install -g 0x2f@1.0.0` only after that version is available. Retain
   the phone/self-hosting experimental label unless the corresponding gates
   have passed. Public website deployment is a separate action.
4. Recheck installation, first task, persisted result, TUI and local Web from
   the public artifact. Update the qualification record with actual registry,
   CI and site evidence; do not infer success from the local archive.

No push, tag, registry change, external announcement or production deployment
is performed by this checklist.

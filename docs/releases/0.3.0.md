# 0x2F0.3.0 — release scope and upgrade

Release date:2026-11-02. npm `0x2f@0.3.0`, tag `v0.3.0`.
Local work routing for macOS and Linux/POSIX, Node.js≥20. Current platform
verification uses macOS arm64/Node26.11.1 and Ubuntu26.04.1 x86_64/Node26.13.0.

## Changes since published0.2.0

- CANCEL targets the current execution occurrence, waits for the owned process
  group and preserves partial artifacts. Recovery distinguishes dead/mismatched
  process identity; saved numeric PIDs do not grant future signaling authority.
- Git task worktrees separate executions from the original checkout. Immutable
  snapshots and saved patches support review and explicit apply. Archive/restore
  retain unfinished bytes; cleanup refuses unsupported ignored/index/reserved
  states instead of deleting data. Shared mode still permits external writers.
- Project-configured checks freeze argv/timeout plans before launch and retain
  actual output hashes and exit receipts. They execute as the host OS user,
  outside provider sandboxing. READY/check success is separate from human ACCEPT.
- Exact per-attempt input/context receipts retain notes, current rules, decisions
  and earlier results within explicit size limits. Tool evidence stays bound to
  its execution. Fresh-session continuation differs from native provider resume.
- Explicit Linux remote-host commands use strict known hosts and recheck the
  pinned machine identity on the actual execution connection. The work executes
  on that host; tasks, dirty files and credentials are not migrated between hosts.
- Quiescent private backup retains a self-contained workspace, Git and task state;
  integrity-checked restore uses a new root and disables execution/replay authority,
  relay credentials and host profiles. It does not automatically launch work.
- Web/mobile surfaces add task creation, correction and occurrence-bound CANCEL;
  refused/ambiguous mutations preserve draft or require inspection. TUI/Web review
  exposes saved runs, input, changes and independent check evidence.
-057 may observe0x2F externally through its opt-in engineering reader. No057 Core,
  renderer or Mobile public application is bundled or publicly upgraded by0.3.0.

## Upgrade and rollback

1. Quiesce old workers and other writers; inspect active tasks before service stop.
2. Preserve the previous prefix, service configuration and a consistent private
   workspace/state backup. Backups can contain secrets; retain owner-only access.
3. Install the published0.3.0 into a separate prefix, verify it, then update the
   normal launcher/service during quiescence. Preserve pairing, machine identity,
   enabled/linger state, settings and provider defaults.
4. Keep a matching0.3.0 executable for new isolated tasks. Old0.2.0 does not own
   their checkout/execution contracts and must not execute them against source.
5. For rollback, quiesce the new runtime and restore the matching prior prefix
   and consistent old state, retaining newer evidence. Restored work has no live
   credentials/host/execution authority; configure trust deliberately afterward.

## Limits and deferred work

Worktrees/check environments are not OS sandbox containment. Escaped process
 groups, universal per-harness permission/resume/cancel parity, acknowledged live
steering, closed-client push, independent phone registrations, host-to-host task
migration, cold reboot/production rollback drills and long-duration thermal/pixel
behavior are not newly qualified. Mobile interruption/runtime-error recovery
remains UNVERIFIED in a separate owner-approved follow-up; it is not a0x2F gate.
No App Store/notarized057/Mobile distribution is part of this release.
